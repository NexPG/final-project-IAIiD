# Аннотационная инструкция

**Статус:** рабочая версия для test  
**Владелец:** Владимир Егоров, контроль — Айдар Мугизов  
**Связано:** [`data.md`](data.md), §8

## 1. Цель

Разметить обращения SpotifyCares в 7 классов так, чтобы:

- test был **human-verified**;
- два разметчика работали независимо;
- Cohen's kappa ≥ 0.70;
- спорные случаи разбирал третий участник.

Разметчик видит только текст и поле `label`. Слабые метки, предсказания модели и метки второго разметчика ему не показываются.

## 2. Классы

| Класс | Что относим | Что не относим |
|---|---|---|
| `payment` | Списание, двойное списание, чек, возврат, карта, платёжная ошибка | Тариф, продление, отмена плана |
| `subscription` | Тариф, Premium, продление, отмена, семейный доступ, промо | Списание денег и чеки |
| `account` | Вход, пароль, 2FA, взлом, профиль, удаление данных, e-mail | Оплата подписки |
| `app` | Плеер, звук, зависания, офлайн, устройства, интерфейс, установка | Наличие трека в каталоге |
| `recommendations` | Подборки, вкусы, лайки, «почему мне это советуют», запросы функций | Наличие конкретного трека |
| `content` | Каталог, права, исчез/недоступен трек или альбом, метаданные | Техническая ошибка плеера |
| `other` | Понятный запрос вне тем: партнёрство, пресса, вакансии, общие жалобы | Неопределимый текст |

## 3. Правила

1. **Одна главная тема.** Если тем две и они равнозначны, выберите `other` и отметьте в `notes` («две темы»). На этапе арбитража такие случаи можно исключить из test.
2. **Отрицание важнее ключевого слова.** «I don't want to cancel my subscription, I need a receipt» → `payment`.
3. **Оплата vs подписка.** Есть транзакция, сумма, чек, возврат → `payment`. Есть план, срок, отмена, продление → `subscription`.
4. **Аккаунт vs подписка.** Проблема входа/пароля/взлома → `account`, даже если упомянута подписка.
5. **Приложение vs контент.** Не играет, зависает, ошибка плеера → `app`. Трек исчез из каталога или недоступен по региону → `content`.
6. **Рекомендации.** Жалоба на подборки или запрос новой функции → `recommendations`.
7. **Спам, реклама, оскорбления без темы** → `other`.
8. **Нечитаемый текст** (только ссылки, эмодзи, обрывки) → `other` и `notes=unreadable`.
9. **Язык.** Если текст не на английском и вы не уверены — `other` и `notes=language`.
10. **PII.** Не копируйте email/телефоны в `notes`.

## 4. Порядок работы

1. Получите файл `batch_all_a.csv` или `batch_all_b.csv`.
2. Заполняйте только `label` и, при необходимости, `notes`.
3. Не открывайте `key_all.csv` и файлы другого разметчика.
4. После заполнения отправьте файл ответственному.
5. Расхождения попадут в `disagreements.csv`; третий участник размечает их вслепую.
6. Итоговый файл `human_verified.csv` используется как test и balanced stress subset.

## 5. Команды

Экспорт Gate 3: стратифицированные 400 примеров из 20% frozen test.

```bash
python scripts/export_annotation_batch.py --split test --limit 400 --min-per-class 25
```

Текущий batch: 400 строк, поддержка классов `payment 25, subscription 47, account 25, app 25, recommendations 11, content 5, other 262`.

Слияние:

```bash
python scripts/merge_annotations.py \
  --a data/annotation/batch_test_a.csv \
  --b data/annotation/batch_test_b.csv
```

После арбитража:

```bash
python scripts/merge_annotations.py \
  --a data/annotation/batch_test_a.csv \
  --b data/annotation/batch_test_b.csv \
  --adjudicated data/annotation/adjudicated.csv
```

Проверка Gate 3:

```bash
python scripts/check_gate3.py
```

Скрипт проверяет 400 строк, kappa ≥ 0.70, отсутствие утечек из train и считает финальные метрики + 95% CI.

## 6. Критерии приёмки

| Критерий | Порог |
|---|---|
| Cohen's kappa | ≥ 0.70 |
| Доля разрешённых расхождений | ≥ 95% |
| Покрытие классов в test | ≥ 25 на класс или явное ограничение |
| Human-verified в test-подвыборке | 100% |
| Размер Gate 3-подвыборки | 400 |
| Утечка conversation_id между split | 0 |

## 7. Что делать при низком kappa

1. Разобрать 20 худших расхождений.
2. Уточнить границы классов в этой инструкции.
3. Провести калибровочную сессию на 20 примерах.
4. Повторить разметку спорного блока.
5. Если kappa всё равно < 0.70, честно указать это в отчёте и увеличить долю `manual_review`.
