# Использование ИИ-ассистентов

**Источник требований:** [`TZ.md`](../01_task/TZ.md), §13; вебинары В15–В16.

## 1. Принцип

ИИ-ассистент использовался как исполнитель рутины, а не как автор проекта. Команда ставила задачу, выбирала данные и метрики, принимала архитектурные решения, интерпретировала эксперименты, проверяла результаты и готовила защиту. Ассистенту отдавались механические и повторяющиеся операции: шаблонный код, склейка шагов в единый pipeline, черновики автотестов, прогон проверок и поиск багов.

Ответственность за любой результат остаётся на команде: каждый сгенерированный фрагмент проверялся запуском, тестами, линтерами и сверкой с артефактами.

## 4. Что ассистент не делал

- не выбирал кейс и таксономию;
- не выбирал источники данных и правила разметки;
- не принимал архитектурные решения;
- не выбирал модель и порог по существу;
- не интерпретировал метрики и не писал выводы;
- не формулировал ограничения, риски и этические оговорки;
- не готовил защиту и не отвечал за решения на Q&A.

## 5. Протокол проверки

1. Код: review, запуск, `ruff`, `mypy`, `pytest`, лицензии.
2. Данные: ручная проверка маппинга, дедупликация, контроль стратификации.
3. Текст: сверка каждого числа с `artifacts/` и `manifest.json`.
4. Безопасность: нет секретов и PII, зависимости проверены.
5. Воспроизводимость: чистый запуск по README.

## 6. Примеры промптов

Промпты формулировались без PII и секретов и ограничивались рутиной:

1. «Сгенерируй argparse-обёртку для существующей функции сборки датасета; не меняй логику».
2. «Собери вызовы шагов pipeline в один скрипт по порядку; пути вынеси в аргументы».
3. «Напиши черновик pytest для этого обработчика; отметь, какие случаи требуют ручной проверки».
4. «Прогони тесты и найди причины падений; не исправляй, сначала перечисли гипотезы».
5. «Сверстай таблицу результатов из JSON в Markdown; числа не округляй».

Результат каждого промпта проверялся запуском кода и сверкой с артефактами.

## 7. Чек-лист проверки AI-кода

- [x] Код запускается на чистом окружении.
- [x] Нет секретов и PII.
- [x] Обработаны пустые и некорректные входы.
- [x] Нет `except: pass` и скрытых ошибок.
- [x] Есть тест или воспроизводимая команда.
- [x] Зависимости и лицензии проверены.

## 8. Безопасность

- реальные PII и секреты не отправлялись;
- сырые TWCS/Bitext анализировались локально;
- LLM не используется в инференсе сервиса;
- сгенерированный код проходит review и тесты до коммита.
