**Статус:** ведётся постоянно  
**Источник требований:** [`TZ.md`](../01_task/TZ.md), §13; вебинары В15–В16

## 1. Принцип

ИИ-ассистенты разрешены. Команда отвечает за проверку любого результата. В отчёте описывается: для какой задачи применялся ассистент, что проверено и что исправлено.

## 2. Что нельзя отправлять

- реальные PII;
- секреты, токены, пароли;
- закрытые данные преподавателя/компании.

## 4. Протокол проверки

1. Код: review, запуск, линтеры, тесты, лицензии.
2. Данные: ручная проверка, дедупликация, контроль стратификации.
3. Текст: сверка с артефактами.
4. Безопасность: секреты, PII, зависимости.
5. Воспроизводимость: чистый запуск.

## 5. Правила команды

1. Не отправлять PII и секреты.
2. Любой сгенерированный код — после review и тестов.
3. Любые сгенерированные данные — после ручной проверки.
4. Test-метки и их ограничения явно описываются в отчёте.
5. Все числа в отчёте — только из артефактов.
6. Сырые TWCS/Bitext-данные не отправляются ассистенту целиком; анализируются локально.

## 6. Примеры промптов

Промпты формулировались без PII и секретов:

1. «Проверь TZ на соответствие 16 вебинарам; верни список несоответствий, не переписывай текст».
2. «Предложи структуру `HalvingRandomSearchCV` для 4 семейств; объясни, какие параметры и ресурсы использовать».
3. «Найди ошибки в тестах FastAPI; не меняй код, сначала объясни причину падения».
4. «Сгенерируй 5 edge cases для классификации обращений; пометь, какие требуют ручной проверки».

Результат каждого промпта проверялся запуском кода/тестов и сверкой с документацией.

## 7. Чек-лист проверки AI-кода

- [x] Код запускается на чистом окружении.
- [x] Нет секретов и PII.
- [x] Обработаны пустые/некорректные входы.
- [x] Нет `except: pass` и скрытых ошибок.
- [x] Есть тест или воспроизводимая команда.
- [x] Зависимости и лицензии проверены.

## 8. Что не делегируется

- финальная архитектура;
- разметка и арбитраж;
- выводы экспериментов;
- безопасность и приватность;
- ограничения и этика;
- защита проекта.
