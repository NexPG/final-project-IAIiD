# План данных и разметки

**Статус:** draft, требует утверждения  
**Связано:** [`TZ.md`](TZ.md), §6

## 1. Главный вывод

**Готового русского датасета обращений в поддержку музыкального сервиса нет.** Публичные датасеты поддержки (Bitext, Tobi-Bueck и аналоги) — англоязычные/немецкоязычные, с другой таксономией и лицензиями. Их нельзя просто взять и обучить русскую модель без перевода, который создаст новые риски.

Поэтому данные собираем сами:

- существующие 420 синтетических обращений — только seed;
- новые примеры пишем/проверяем вручную;
- синтетика допустима только в train;
- test и validation — human-verified и заморожены.

- test 84 примера, по 12 на класс — слишком мало для устойчивой оценки;
- разметка не проверена оператором;
- нет `channel` и `locale`;
- только `source=synthetic`;
- confidence не калиброван;
- threshold 0.0, automation disabled;
- метрики 0.929 получены на синтетическом test, а не на реальном потоке.

## 4. Источники и правила

| Источник | Объём | Как используем | Ограничение |
|---|---|---|---|
| Старые 420 | 420 | Аудит, seed train | Не в финальный test |
| Сценарии команды | 140+ | Новые формулировки | Проверять вручную |
| Human-written | 500–700 | Train/val/test | Основной доверенный источник |
| LLM-генерация | 150–300 | Только train | Ручная проверка, маркировка |
| Реальные обезличенные тикеты | 0–N | Внешняя валидация | Если появятся, не коммитить |

**Правила:**

1. Синтетика не попадает в validation/test.
2. Test пишется/редактируется человеком, а не генерируется тем же шаблоном.
3. Один `scenario_id` не пересекает split.
4. Near-duplicates ищутся по нормализованному тексту и char n-grams.
5. Разметчик не видит предсказания модели.
6. Спорные примеры идут в арбитраж.

## 5. Аннотационная инструкция

### 5.1. Определения

| Класс | Определение | Не путать |
|---|---|---|
| `payment` | Транзакция, списание, чек, возврат, карта | С тарифом/отменой подписки |
| `subscription` | План, продление, отмена, семейный доступ, промо | С платежной ошибкой |
| `account` | Вход, пароль, 2FA, профиль, безопасность, удаление | С платежом за подписку |
| `app` | Плеер, звук, зависания, офлайн, устройства, UI | С каталогом |
| `recommendations` | Персональные подборки, вкусы, лайки | С наличием контента |
| `content` | Каталог, права, треки, альбомы, метаданные | С техпроблемой плеера |
| `other` | Понятный запрос вне тем | С неопределимым текстом |

### 5.2. Спорные случаи

| Пример | Решение |
|---|---|
| «Не могу войти, чтобы отменить подписку» | Если главная проблема — вход → `account`; если отмена → `subscription`; при равенстве → manual |
| «Пропал трек из плейлиста» | Если трек есть, но не играет → `app`; если исчез из каталога → `content` |
| «Списали деньги и не работает приложение» | Две темы; при близких вероятностях → manual |
| «Подписку отменять не хочу, нужен чек» | `payment` (главное намерение — чек) |
| «Вы лучшие» | `other` или manual, если нет темы |
| Спам/реклама | `other` → general_support или manual |

### 5.3. Протокол

1. Два разметчика на 200+ примерах.
2. Cohen's kappa ≥ 0.70.
3. Расхождения — третий участник.
4. Спорные случаи добавляются в инструкцию.
5. Инструкция версионируется.

## 7. Валидация

### 7.1. Pandas-проверки

1. Обязательные поля.
2. Пропуски.
3. Типы.
4. Уникальность `id`.
5. Длина текста.
6. Наличие букв.
7. Допустимые классы.
8. Допустимые split.
9. Допустимые source.
10. `scenario_id` не пересекает split.
11. Один сценарий — один класс.
12. В каждом split все 7 классов.
13. Доля синтетики.
14. PII-паттерны.
15. Near-duplicates.

### 7.2. Great Expectations

Минимум 5 expectations:

1. `text` not null.
2. `label` in set.
3. `split` in set.
4. `id` unique.
5. `scenario_id` unique within split (custom/group check).
6. `text` length between 10 and 5000.
7. `source` in set.
8. synthetic share in eval = 0.

Дополнительно:

- dirty copy с 5+ ошибками;
- validation result JSON;
- DataDocs HTML;
- обучение останавливается при провале.

## 8. Приватность

- Реальные PII не собираем.

- Сырые данные не коммитятся.
- Доступ к данным — только у команды.
- После защиты данные удаляются.

## 12. Если данных меньше

Если команда не успевает собрать 1 050:

- минимум 700 (100 на класс);
- test 140 (20 на класс);
- обязательно human-verified;
- в отчёте указать: «малый test, широкий доверительный интервал, метрики не подтверждены на реальном потоке»;
- automation не включать без запаса по precision.

Лучше честный малый датасет, чем красивый синтетический test.
